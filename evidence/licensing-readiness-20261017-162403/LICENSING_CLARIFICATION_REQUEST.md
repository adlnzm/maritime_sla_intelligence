Prepared: 17 October 2026 (Asia/Qatar).
Proposed recipient: subscriptions@un.org; technical interpretation contact, if appropriate: comtrade@un.org.
Subject: Clarification for public portfolio demo using limited UN Comtrade context and possible future commercial use

Dear UN Comtrade team,

We are developing a portfolio and demonstration platform for maritime risk and supply-chain decision support. The application, dashboards and project repository may become publicly accessible. UN Comtrade is not integrated into the running application. A small real API sample has been retained locally for source qualification. Our existing operational source is IMF PortWatch; any trade statistics would remain separate national context, not vessel congestion, waiting-time or shipment-performance observations.

We are considering a limited demonstration using annual/monthly national merchandise-trade totals for Singapore, the Netherlands, China, the United States and the United Arab Emirates. Potential uses include displaying a few source-derived statistics, calculating clearly labelled aggregate indicators or growth rates, and caching a bounded set of responses for reproducibility. A public repository could contain code, documentation and possibly small evidence/fixture samples. Raw-data downloads, API redistribution and public raw-response archives are not enabled for Comtrade and remain undecided. We can omit them. Exact record limits, revision retention, refresh frequency and cache duration would be set before implementation.

The immediate purpose is a portfolio demonstration. Charging for access is not established; future commercial use is possible and would be reviewed separately. Please clarify:

1. Which permission or exception applies to this public demonstration, separately for displayed values, calculated aggregates/growth rates, cached responses, small repository samples and any downloadable/API data?
2. How should we reconcile the commercial small-dataset exception with the paid-application and premium-subscription requirements elsewhere in your redistribution guidance? What changes would be required before a future paid service?
3. How should total records be counted across cached revisions, fixtures, backups, exports and public repository copies? What conditions apply to retention, updates and third-party reuse?
4. What attribution, licence links, disclaimers and transformation documentation are required? Does a plain link to your portal without reproducing data require any additional permission?
5. Which access tier/API is appropriate for this small periodic use, and what authentication, request/record limits, throttling and redistribution conditions apply? Please identify any required licence or subscription and its scope; this inquiry does not authorize a purchase.

We would appreciate written confirmation of the permitted scope and applicable terms before implementation. We will not interpret a lack of response as approval.
