## Actual proof-of-access and caveats

Read-only Python `requests.get` calls used timeouts of 20–25 seconds. Initial sandbox DNS failures are retained as `sandbox_attempt_error`; approved network access subsequently reached the official endpoints. Exit 0 for the capture script means evidence was written, **not** that every HTTP response was usable. Individual status/body interpretation is recorded above.

- `port-access-results.json` records seven exact URLs, request timestamps, HTTP codes, response sizes and SHA-256 values. Matching `.response.txt` files retain responses. Times are acquisition times, never observation times.
- `singapore-data-access.json` and `singapore-latest-months.response.json` retain the three-row query (HTTP 200, `success:true`, descending monthly order). Catalogue metadata has an inconsistent `coverageEnd` of **2023-08-31** although actual records extend to August 2026; use inspected record periods, not that catalogue field, for this assessment. `lastUpdatedAt` is September 2026 and is not an observation.
- `la-report-access.json` records raw PDF capture results. The web research tool extracted the operations report date and the import-dwell timestamp from the reports themselves. No LA/LB-wide daily `portcalls` sequence was obtained. The dwell report does not state a timezone, so no exact UTC age is asserted.
- [data.gov.sg rate limits](https://guide.data.gov.sg/developer-guide/api-overview/api-rate-limits): datastore search allows 4/8/20 requests per ten seconds without/dev/prod key; respect HTTP 429. [Open Data Licence](https://data.gov.sg/open-data-licence) requires conspicuous source acknowledgement and current licence link; excludes personal/third-party rights and endorsement. These permissions do not automatically extend to authenticated MPA operational products.
- All non-Singapore-ODL licences and all unlisted rate limits remain **unverified**, not unrestricted. Official provenance does not imply permission to scrape or redistribute.

## Recommended separate implementation step

Retain PortWatch as the existing cross-port activity source, conditional on its independent freshness gate; none of the candidates demonstrated a drop-in, genuinely current six-port equivalent. Keep stale PortWatch publication blocked. Prioritise a small **LA daily operational corroboration adapter**, subject to terms review, because current reports are actually accessible. Store container dwell, berth vessel count and 40-NM vessels as distinct measures with their native geography. Test business-day gaps, date parsing, missing timezone, changed PDF layout, report revisions, stale reports, HTML error bodies masquerading as HTTP 200, and incomplete LA/LB coverage. Do not map these measures into `portcalls` or shipment SLA outcomes.

In parallel seek approved Singapore MPA and Rotterdam event APIs; obtain actual sample records and data dictionaries before selecting them. Shanghai TIP, NY/NJ email dashboard and Dubai Trade require further access/schema/rights work. Add monthly government statistics only to a separate contextual or retrospective reconciliation layer. Every future adapter must retain native period/timezone, retrieval time, source URL, content checksum, vessel/category scope, licence and an explicit `OBSERVED`/`DERIVED`/`ANTICIPATED` distinction. Reconcile comparable aggregates without making incompatible metric differences look like source errors.

No new provider integrated; no all-six-port freshness success or release-readiness claim follows from this research.
