# Maritime operations Power Platform source

These are generated source and contract assets, not a deployed app, managed solution, or verified tenant connection. Regenerate with `PYTHONPATH=src python scripts/build_power_platform.py`; extend the existing report with `python scripts/build_powerbi.py --operations`. Neither command runs the product.

## Connection prerequisites

Configure the existing API for Entra authentication (`MARITIME_AUTH_MODE=entra`, `AZURE_TENANT_ID`, `AZURE_API_AUDIENCE`) and expose HTTPS. Use the existing `Maritime.Reader` and `Maritime.Operator` roles. Reviews derive identity from the verified token's `oid`; local shared keys are development-only identities. Assign users and the automation connection deliberately. Configure a durable `MARITIME_WORKFLOW_DIR` and `MARITIME_WORKFLOW_CONFIG` pointing to a validated copy of `configs/workflow.json`. Empty recipients cause an auditable exception, never a fabricated successful delivery. Do not put credentials in these files.

The operational backend is SQLite in a separate directory. A durable single-host API deployment is required for this implementation. Multi-replica shared SQLite on network storage is not certified. Hosting, backup/restore of the separate workflow.db, access controls, retention, monitoring, and concurrency load validation require operational acceptance before production.

## Power Apps

Import `connector/openapi.json` as a custom connector after replacing placeholder host, tenant, API application ID, and OAuth scope with approved values. Configure OAuth credentials and redirect URI inside the tenant; do not hard-code secrets. Add the connector to a canvas app with the exact data source name `MaritimeOperations`.

Create screen `OperationsReview`, paste `canvas/controls.fx.yaml` through Studio code view, and set the formulas in `canvas/Screen.properties.json` and `canvas/App.properties.json` in Studio. The leading `=` identifies formulas in source. `canvas/OperationsReview.pa.yaml` is a schema-checked source reference, not an editable/importable .msapp package: Microsoft treats generated .pa.yaml as read-only. Studio must compile and validate the controls/formulas and connector signatures. No canvas rendering or deployment has been performed.

The app requests only flagged weeks, uses server filters and 100-row paging, and displays risk facts, freshness, quality, provenance and simulation markers. Server rules enforce reasons, stronger IGNORE justification, immutable history, authenticated identity, idempotency and optimistic conflicts. A disabled save button is a convenience; server authorization and data validation remain authoritative.

## Power Automate

`automate/GoldRiskEscalation.definition.json` is a schema-validated workflow definition to configure in a solution/flow with the connection references in the adjacent JSON. It is not a solution import ZIP. Recurrence polls the durable event outbox every five minutes; concurrency is one. All risk transitions are generated by the service from approved Gold; there are no thresholds in the flow. Bind the custom API and Office 365 Outlook connections, approve recipients, and validate designer import and delivery permissions.

Claims have leases. Successful, failed, expired, and recipient-less attempts are recorded with timestamps. Retry is bounded and terminal exceptions remain visible. A SENT acknowledgement records the connector result; it is not proof the human received/read the email. Delivery is at-least-once: an accepted email followed by a lost acknowledgement can be resent after lease expiry. The stable event ID in the subject supports reconciliation; exactly-once external email delivery is not claimed. Audit-retained EXCEPTION records require operator investigation; automatic terminal-exception recovery is deliberately absent.

## Power BI

The existing `fabric/powerbi/Maritime.Report` now contains ten pages (the existing five plus review queue, history, escalation tracking, Hamad, portfolio). It remains unbound until a real semantic model ID is supplied. `reporting/model-contract.json` defines table columns and many-to-one, single-direction relationships from review/event history to `fact_port_weeks.review_id`. Focus and queue tables are server-filtered views, not independent risk calculations. Historical actions may outlive the current rolling Gold window; keep them visible as history and do not discard unmatched records.

Use `scripts/export_operations.py --api-url https://<approved-api> --output <new-snapshot.json>` with a short-lived operator token supplied through `MARITIME_EXPORT_ACCESS_TOKEN`. It calls the real authenticated reporting endpoint, uses a 30-second timeout, disables redirects, validates required tables, and refuses to overwrite snapshots. This command was tested with an in-process API only, not a live endpoint.

Create a text parameter `OperationsSnapshotPath`, add `reporting/OperationsSnapshot.pq`, then the five table queries from `reporting/*.pq` with their exact filenames as query names. Add the relationships and `operations-measures.dax` measures to the existing semantic model alongside its current tables. Set import credentials/file permissions and an approved gateway/export-refresh process if scheduled refresh is needed. The snapshot may contain human reasons and identities: restrict its access. The API's Hamad table is pinned through `focus_port_id=port2026`.
